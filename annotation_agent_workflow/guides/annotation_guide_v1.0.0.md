## 1. 项目背景、目标与非目标

### 1.1 背景

本项目从电子病历中发现肺炎相关公共卫生信号，使后续人员能够回到原文复核。系统提供的是“值得复核的信号”，不是肺炎临床诊断，也不能替代医生、实验室或疾控调查结论。

### 1.2 最终用途

标签只在能支持以下至少一项用途时保留：

1. 判断病例是否进入肺炎相关复核队列；
2. 排除明显无关、纯既往或证据不足的病例；
3. 对复核优先级进行排序；
4. 说明系统为何给出该病例级判断。

医学上有意义、但不改变上述用途的细节，不进入v1人工标签。

### 1.3 本指南不处理

- 不标病例间空间聚集、14天聚集或传播链；这些由地址地理编码和GIS算法处理。
- 不根据医学常识补造原文没有写出的肺炎、病原或因果。
- 不评价治疗是否正确。
- 不穷举全部症状、疾病和用药。
- 不构建完整的BEFORE/AFTER时间图。
- 不把“病原体阳性”自动等同于“肺炎”。

### 1.4 三条总原则

1. **原文优先**：只标文本明确表达的内容。
2. **病例目标优先**：先判断该信息是否会改变病例纳入、排除、优先级或解释。
3. **不确定时保守**：不确定的实体不补造，不确定的关系不连；记录问题并交裁决。

## 2. 标注模型与Schema实施状态

本任务分成两个互相关联、但不能混为一谈的层次。

### 2.1 任务A：病例级判断

阅读整份文本，选择且只选择一个结论：

- 目标病例信号
- 待专业复核
- 非目标
- 信息不足

同时保存1—3条最小证据片段。病例级证据可以引用当前XML未覆盖的症状原文，但不能把它私自标成不存在的实体。

### 2.2 任务B：结构化证据

按XML标注与病例判断相关的实体、断言、时间、测量、标本、检测方式和关系。结构化证据服务于模型训练和可解释性，不要求覆盖全文所有医学概念。

### 2.3 当前XML与v1推荐实施

| 功能 | 当前XML | v1推荐 | 生产要求 |
|---|---|---|---|
| 病例级四分类 | 无 | 新增单选 `case_decision` | 必须增加，否则需在外部表单记录 |
| 数据问题 | 无统一控件 | 新增多选或文本 `data_issue` | 推荐增加 |
| 咳嗽、咳痰、气促 | 无 | 各新增1个实体 | 推荐增加；更新前只作病例级原文证据 |
| 时间表达 | 无 | 新增一个通用跨度 | 推荐增加；归一化由程序完成 |
| 当前、既往、持续、进行性加重 | 有 | 保留，但分组解释 | 继续使用 |
| 好转、稳定、频率 | 无 | 不新增 | 记录在病例证据，必要时后处理 |
| 状态、时间、测量、标本、检测方式 | 有 | 保留 | 继续使用 |
| 因果、完整事件时序 | 无 | 不新增 | 不标 |

在生产XML正式更新前，标注员必须以当前XML按钮为准，并把缺失功能记录为 `xml_guide_mismatch`；不得临时创造同义标签。

## 3. 病例级判断

### 3.1 “索引临床事件”

索引临床事件指当前文本所描述的本次门急诊、当前住院或同一次连续诊疗过程。判断“当前或近期”时，以是否属于索引临床事件为准，不用固定天数代替临床语境。

- 同次住院早期有明确肺炎、出院时已好转：仍属于索引临床事件。
- 仅在既往史中提到多年前肺炎、与本次无关：不属于索引临床事件。
- 无法判断是否属于本次事件：进入待专业复核并上报时间问题。

### 3.2 四分类定义

#### A. 目标病例信号

满足以下条件：

1. 索引临床事件中存在至少一条“直接肺部证据”；
2. 证据不是全部被否定、仅为计划、仅为条件假设或仅属于他人；
3. 文本足以确认该证据属于患者。

直接肺部证据见第4.1节白名单。病例已好转、正在治疗或出院，不取消索引事件中明确存在过的肺炎信号，但可降低活动性和复核优先级。

#### B. 待专业复核

不存在足够的直接肺部证据，但满足以下任一情况：

1. 急性发热，加至少一项呼吸证据：咳嗽、咳痰、气促/呼吸困难、低氧、异常肺部体征；
2. 文本写“疑似肺炎、考虑肺炎、不除外肺炎、待排肺炎”；
3. 索引事件中有性质或活动性不明的肺/胸部异常；
4. 呼吸道标本中检出本项目关注的呼吸道病原体，但没有足够肺炎直接证据；
5. 其他证据组合使标注员无法安全判为非目标。

#### C. 非目标

满足以下任一情况，且没有未解释的直接肺部证据：

1. 明确是其他疾病或无关复诊；
2. 孤立轻症，如单独短期咳嗽、鼻塞流涕、咽痛；
3. 长期稳定的慢性呼吸症状，无急性改变；
4. 所有相关证据均被明确否定；
5. 仅有筛查、暴露史或计划检查，且无急性呼吸证据；
6. 仅有纯既往肺炎，与索引临床事件无关。

#### D. 信息不足

文本为空、严重截断、字段错位，或仅有无法归属的项目/数值，使目标、待复核和非目标均无法可靠判断。

“看不懂但明显与肺炎无关”不是信息不足，应判非目标。

### 3.3 判定顺序

按以下顺序执行，不跳步：

1. 文本是否可用？不可用 → 信息不足。
2. 是否有索引临床事件内的直接肺部证据？有 → 目标病例信号。
3. 是否有疑似肺炎、急性发热加呼吸证据、性质不明肺/胸异常或呼吸道病原阳性？有 → 待专业复核。
4. 其余 → 非目标。

### 3.4 证据最小化

病例级证据只保留足以解释结论的1—3条原文片段。不要复制整段病历。优先顺序是：

1. 直接肺部证据；
2. 急性时间和核心症状；
3. 否定、计划、他人或既往等排除信息；
4. 病原、暴露或严重程度证据。

## 4. 证据优先级与病例筛查

### 4.1 直接肺部证据白名单

可直接支持“目标病例信号”的原文包括：

- 明确诊断：肺炎、支气管肺炎、大叶性肺炎、间质性肺炎等；
- 明确感染：肺部感染、两肺感染、下呼吸道感染且上下文明确指肺实质；
- 明确炎症/实变：右肺炎症、两肺炎症、感染性病变、肺实变或影像明确提示肺炎。

必须保留原文语义。不能因为词中含“肺炎”就标肺炎诊断，例如：肺炎支原体、肺炎克雷伯菌、肺炎链球菌。

### 4.2 不能单独作为直接肺部证据

以下内容单独出现时不判目标病例信号：

- 胸水/胸腔积液、气胸、胸膜增厚、脓胸、支气管胸膜瘘；
- 条索影、小斑片影、结节、肿块、纤维化、陈旧性结核、肺不张；
- 双肺呼吸音粗、啰音、胸痛；
- CRP、PCT、白细胞等炎症指标升高；
- 发热、咳嗽、咳痰、气促；
- 病原体阳性；
- “抗感染治疗”或抗菌药物使用。

这些证据可与其他内容共同触发待专业复核。

### 4.3 初步筛查如何兼顾漏筛和过筛

采用两阶段策略，不要求一个规则同时完成所有判断。

#### 阶段0：数据质量门禁

程序先排除空字符串、纯空格、只有分隔符、无法解析的记录，并记录排除原因。不要让医学标注员手工清理大量空任务。

#### 阶段1：高召回粗筛

只要命中以下任一条件就保留给病例级模型或人工：

- 直接肺部证据词；
- 急性发热加呼吸证据；
- 疑似/待排肺炎；
- 性质不明的当前肺/胸异常；
- 呼吸道标本中关注病原体阳性。

阶段1允许多筛，不直接输出“真实病例”。

#### 阶段2：四分类判断

按第3章规则区分目标、待复核、非目标和信息不足。

#### 防止漏筛

- 从阶段1排除的记录中随机抽取5%—10%复核；
- 对含“肺、胸、呼吸、CT、影像、感染、发热”等宽词但被排除的记录加大抽样；
- 分别报告目标/待复核合并后的漏筛数，不能只看总体准确率；
- 一旦发现规则性漏筛，补充规则并回溯同批数据。

#### 防止过筛

- 单独鼻塞、流涕、咽痛、孤立咳嗽不进入待复核；
- 暴露史单独出现不进入待复核，只用于已有呼吸证据病例的优先级；
- 病原体名称或计划检测不等于阳性结果；
- 非特异影像不直接判目标。

## 5. 通用实体跨度规则

### 5.1 最小完整跨度

选择能表达完整医学概念的最短原文，不带否定词、时间词、提示词或标点。

- “CT提示右肺炎症” → 标 `[右肺炎症]`，不含“CT提示”。
- “无发热” → 实体标 `[发热]`，状态标 `[无]`，再连状态关系。
- “今仍有发热” → 实体 `[发热]`；时间/病程修饰分别标 `[今]`、`[仍有]`。

### 5.2 保留必要限定

侧别、解剖部位或能改变概念的限定词应包含在实体跨度中，如“右肺炎症”“两肺感染”。纯程度词通常不并入实体，除非它属于固定结果词，如“弱阳性”作为完整状态跨度。

### 5.3 否定、计划和主体不并入实体

“未见、否认、拟、建议、家属”等另标断言并连接，不与临床实体合并。

### 5.4 不拆词内误标

- `[肺炎支原体]`只标病原体，不在其中再标“肺炎诊断”。
- `[肺炎克雷伯菌]`只标病原体。
- “抗肺炎治疗”若不是明确诊断，不因“肺炎”二字自动标诊断。

### 5.5 重复和并列

- 原文每个明确、独立出现的相关实体都标。
- 同一事实在复制粘贴段落中完全重复时，仍按界面文本标注，但同时记录 `duplicate_text`；预处理阶段应优先去重。
- 并列实体分别标，例如“肺炎支原体、肺炎衣原体IgM阴性”应标两个病原体。

### 5.6 不连续跨度

当前任务不创建不连续实体。若修饰语与实体分开出现，分别标跨度并通过关系连接。

## 6. 实体标签体系

### 6.1 核心肺部实体

| 标签 | 定义 | 纳入例 | 排除例 | 病例作用 |
|---|---|---|---|---|
| 肺炎诊断 | 原文明写肺炎诊断 | 肺炎、支气管肺炎 | 肺炎支原体；待排肺炎需加可疑 | 直接纳入 |
| 肺部感染 | 明确指向肺/两肺的感染 | 肺部感染、两肺感染 | 抗感染治疗；CRP升高 | 直接纳入 |
| 肺部组织炎症 | 影像/病理明确肺实质炎症、感染性病变或实变 | 右肺炎症、两肺炎症 | 胸水、条索影、结节 | 直接纳入或复核 |

### 6.2 症状和严重程度

#### 当前成人XML

- 发热
- 呼吸衰竭
- 休克
- 器官衰竭
- 机械通气

#### 当前儿童XML新增

- 鼻翼煽动
- 三凹征
- 喘鸣喘息
- 意识障碍
- 惊厥
- 拒食或喂养困难
- 脱水征

#### v1推荐最小新增症状

- 咳嗽
- 咳痰
- 气促/呼吸困难

这三个症状只用于与发热、低氧、异常肺部证据等组合判断待专业复核；不新增干咳/湿咳、痰色、频率、程度等子标签。

#### 解释规则

- 发热包括“低热、高热、体温升高”等明确症状表达；单纯数值另标体温测量。
- 呼吸衰竭、休克和器官衰竭提高复核优先级，但不证明病因是肺炎。
- 机械通气是治疗/支持措施，不是症状，也不证明肺炎；保留标签是为了严重程度排序。
- 儿童体征只有原文明确出现才标；“无鼻翼煽动”仍标实体并连接否定。

### 6.3 测量

#### 测量指标

- 成人：体温、呼吸频率、静息状态指氧饱和度、动脉氧分压(PaO2)、吸氧浓度(FiO2)
- 儿童：呼吸频率、静息状态指氧饱和度、动脉氧分压(PaO2)、吸氧浓度(FiO2)

#### 测量组成

- 数值
- 单位
- 比较符
- 阈值判断

例：“SpO2 < 93%”分别标指标、比较符、数值、单位；每个组成部分都通过“测量”关系连接到SpO2。不根据医学常识自行生成“异常”。

### 6.4 流行病学暴露

#### 成人职业

- 医务人员
- 禽、畜类从业人员
- 农牧民等野外作业人员
- 病原微生物实验室检测人员

#### 成人和儿童共同

- 可疑动物或动物制品接触史
- 可疑环境暴露史
- 外出外来史

暴露史只按原文标。否认暴露仍标实体并连接否定。暴露单独出现不触发肺炎待复核；只有病例已有呼吸证据时才提高优先级。GIS聚集不在此处标注。

### 6.5 病原体

#### 病毒

新冠病毒、流感病毒、呼吸道合胞病毒、腺病毒、人偏肺病毒、副流感病毒、普通冠状病毒、博卡病毒、鼻病毒、肠道病毒。

#### 细菌

A族链球菌、百日咳鲍特菌、肺炎链球菌、流感嗜血杆菌、军团菌、肺炎克雷伯菌。

#### 其他

肺炎支原体、曲霉菌、隐球菌、鹦鹉热衣原体、肺炎衣原体。

只标XML列出的病原体。未列出的病原体若可能改变病例判断，记录问题，不私创标签。病原体名称本身不表示检测阳性。

### 6.6 标本

- 咽/鼻咽拭子
- 痰
- 肺泡灌洗液
- 血
- 尿
- 胸水

只有在检测语境中才标标本。例如“痰培养”中的“痰”是标本；“咳痰”中的“痰”是症状内容，不标为标本。

### 6.7 检测方式

- 核酸检测
- mNGS
- 抗原快速检测
- 抗体IgM
- 抗体滴度/双份
- 培养

检测方式必须与原文明确的病原检测对应。计划检测加假设性；未完成的计划不当作结果。

## 7. 时间模块

### 7.1 为什么采用三层轻量模型

原XML中的“当前、既往”描述事件相对位置，“持续、进行性加重”描述病程。具体日期、相对时间和时长又是另一类信息。把这些混成一个互斥分类会造成分歧，因此v1分为三层，但只新增一个人工标签。

### 7.2 第一层：时间表达 `TimeExpression`（推荐新增）

标原文明确出现的时间跨度：

- 绝对日期：`2025-02-16`、`7月15日`
- 相对时间：`今`、`昨日`、`1周前`、`入院前2天`
- 时长：`持续3天`中的`3天`、`反复20年`中的`20年`
- 病程日序：`输液第4天`、`住院第2日`
- 时间窗口：`近7天`、`近期`

人工只选原文跨度，不填写标准日期。程序结合文档时间归一化为日期、时长或窗口。

### 7.3 第二层：事件相对位置

#### 当前

明确表示索引临床事件当前状态的词，如“今、今日、目前、现、本次”。只标原文存在的提示词，不给普通陈述补造“当前”。

#### 既往

明确表示非索引事件的过去史，如“既往、曾经、数年前患有”。具体日期不自动等于既往；同次住院早期日期仍属于索引事件。

#### 未来/计划

当前XML不设“未来”。用假设性/计划断言表达“拟、计划、建议、将行”。

### 7.4 第三层：病程

#### 持续

提示事件仍存在或治疗后未改善，如“仍有、一直、持续、未愈、无好转、效不佳”。

#### 进行性加重

只有明确逐步恶化时标，如“逐渐加重、进行性恶化、持续加重”。单次“今日加重”表示当前变化，不自动等于进行性。

#### 好转/稳定

不新增人工标签：

- “好转、缓解”保留在病例级证据中，用于降低活动性/优先级；
- “稳定”通常不改变是否存在过肺炎；
- 若索引事件中已有明确肺炎，不能仅因出院时好转改判非目标。

### 7.5 时间关系

只有时间词明确修饰某个临床事件时才连“时间”关系。

- “今仍有发热” → 今—时间—发热；仍有—时间—发热。
- “1周前发热，今日咳嗽” → 1周前只连发热；今日只连咳嗽。
- “既往肺炎，本次无发热” → 既往只连肺炎；无只连发热。

不要因为同句出现就把所有时间词连接给所有实体。

### 7.6 时间归一化建议

导出后程序可生成以下派生字段，人工不直接标：

- `normalized_date_or_interval`
- `in_index_episode`
- `activity`: active / improving / resolved / unclear
- `course`: ongoing / worsening / unclear

这些字段用于模型和复核排序，不增加标注界面复杂度。

## 8. 断言模块

### 8.1 标签定义

| 标签 | 提示词/例子 | 解释 |
|---|---|---|
| 肯定 | 阳性、检出、培养见、证实、弱阳性 | 原文明确报告存在；弱阳性保留完整跨度 |
| 否定 | 无、未见、否认、阴性、未检出、不伴 | 明确不存在或检测阴性 |
| 可疑 | 疑似、考虑、不除外、待排、可疑阳性、临界 | 不当作确诊或确定阳性 |
| 条件性 | 若、如出现、必要时 | 条件尚未满足 |
| 假设性 | 拟、计划、建议、将行 | 计划或预期，未证明已发生 |
| 与患者本人无关 | 家属、母亲、接触者、同事 | 事件不属于患者本人 |

### 8.2 默认规则

普通肯定陈述没有显式提示词时，只标临床实体，不补造一个不存在的“肯定”跨度。病例逻辑可把没有否定/可疑/计划/他人提示的普通陈述视为患者当前存在，但这一默认值由后处理完成。

### 8.3 病原检测映射

- “阳性、检出、培养见、弱阳性” → 肯定。
- “可疑阳性、临界、不排除污染” → 可疑。
- “阴性、未检出” → 否定。
- 仅出现病原体和检测方式、无结果词 → 不补断言。
- “拟行新冠核酸” → 新冠病毒/核酸检测加假设性，不算已检测。

### 8.4 作用域

一个修饰词共同作用于多个实体且语法明确时，对每个实体分别连边。

“无咳嗽、发热、气促”中，“无”分别修饰三个症状。若并列结构不清，宁可少连并上报，不能猜测。

## 9. 关系模块

### 9.1 关系的目的

实体说明“有哪些证据”，关系说明“修饰语、数值、标本和方法属于哪一条证据”。关系错误可能把阴性变阳性或把一个病原体的标本连给另一个，因此关系必须比实体更保守。

### 9.2 Label Studio中的方向

Label Studio当前 `Relation` 标签文档只定义关系值和显示颜色，没有独立的“无向边”配置参数。界面创建关系时会产生起点和终点，但本项目不把点击先后当作医学业务方向。

本项目采用“逻辑无向、语义有角色”的方式：

- 标注员只需选对两个端点和关系类型；
- 导出后按端点标签自动归一化为 `modifier → target`、`specimen → pathogen` 等标准角色；
- 评分时若两个端点和关系类型相同，不因点击顺序相反扣分。

这能降低操作复杂度，同时保留明确的医学含义。

### 9.3 合法端点矩阵

| 关系 | 语义角色A | 语义角色B | 合法例 | 非法/不充分例 |
|---|---|---|---|---|
| 状态 | 肯定/否定/可疑/条件性/假设性/他人 | 症状、诊断、暴露、病原体或检测 | 阴性—肺炎支原体 | 同句的阴性连到无关病原体 |
| 时间 | 当前/既往/持续/加重/时间表达 | 症状、诊断、暴露或检测事件 | 1周前—发热 | 因同句出现而连全部实体 |
| 测量 | 数值/单位/比较符/阈值判断 | 测量指标 | 38.3—体温 | 38.3连到呼吸频率 |
| 标本 | 标本 | 相应病原体 | 痰—肺炎克雷伯菌 | 胸水连到尿培养病原体 |
| 检测方式 | 检测方式 | 相应病原体 | IgM—肺炎支原体 | 核酸连到仅做抗体的病原体 |

### 9.4 逐关系规则

#### 状态

- 每个被修饰实体各连一条边。
- “不除外肺炎”用可疑，不用否定。
- “肺炎支原体IgM阴性”中阴性连病原体；IgM用检测方式关系连病原体。

#### 时间

- 只连接语义上被修饰的事件。
- 同一时间表达可以连接多个事件，但必须语法作用域明确。
- 不根据常识推断“先发热后肺炎”等未明说关系。

#### 测量

- 指标、数值、单位、比较符分别标，所有组成连接到对应指标。
- 多项生命体征并列时按最近且语义唯一的指标配对。

#### 标本

- 标本必须处于检测语境。
- “痰培养见肺炎克雷伯菌” → 痰—标本—肺炎克雷伯菌。
- “咳痰，肺炎支原体IgM阴性”不能把症状中的“痰”连到支原体。

#### 检测方式

- 每种方法只连其实际检测的病原体。
- 并列清晰时逐项连边。
- 方法被多个病原共享且作用域明确时，可分别连边。

### 9.5 不标的关系

- 症状导致诊断
- 暴露导致感染
- 病原体导致肺炎
- 药物治疗疾病
- BEFORE、AFTER、OVERLAP等完整事件时序
- 仅因两个实体在同一句或相邻句出现而产生的关系

### 9.6 关系不确定时

1. 先确认两个端点是否都标对；
2. 再确认原文是否明确表达归属；
3. 若有两种合理连接，暂不连；
4. 在反馈中写出最小片段、两种解释和对病例判断的影响。

## 10. 数据质量门禁

“数据质量门禁”是指在病历进入医学标注前，用程序检查它是否值得进入任务队列，不是医学纳排标准。

### 10.1 导入前自动排除

以下记录不进入普通标注队列，另写排除日志：

- `text`缺失、空字符串或纯空格；
- 去除标点/分隔符后没有有效文字；
- 任务JSON无法解析；
- 文本完全重复且已有同源任务；
- 仍含姓名、证件号、电话、精确住址等身份信息。

日志至少保存任务号、排除原因、规则版本和时间，不保存额外身份信息。

### 10.2 进入标注后发现的问题

| 问题 | 动作 |
|---|---|
| 部分截断但仍可判断 | 正常分类，记录 `truncated` |
| 明显拼接错误且不影响结论 | 不纠正文，跳过错误片段并记录 |
| 拼接错误可能改变结论 | 阻塞，退回数据修复 |
| 大段重复 | 标可用部分，记录 `duplicate_text` |
| 仍有身份信息 | 立即停止该例并按项目隐私流程处理 |

### 10.3 “很多病历不相关”如何处理

无关病历本身是“非目标”训练数据，不应全部在导入前删除。建议：

- 空白、损坏、重复、含身份信息由门禁排除；
- 医学内容完整但与肺炎无关的记录保留一部分，作为真实负例；
- 通过分层抽样控制正例、待复核、硬负例和普通负例比例；
- 不要只用关键词命中的病历训练，否则模型无法学习排除无关内容。

## 11. Label Studio操作流程

### 11.1 每例操作顺序

1. 检查文本可用性和去标识化。
2. 阅读主诉、现病史、检查摘要和相关后文，形成病例级初判。
3. 标直接肺部证据和最小症状证据。
4. 标断言、时间和病程提示词。
5. 标与病例解释相关的测量、病原、标本、检测方式和暴露。
6. 按合法端点建立关系。
7. 回看病例级结论，保存1—3条最小证据。
8. 记录数据问题或指南问题。

### 11.2 不要做的事

- 不因担心漏标而把所有医学词都标出来。
- 不把模型预标注当成正确答案。
- 不自行修改原文、标签名或关系名。
- 不在无法确定关系时随意连最近实体。
- 不用个人临床经验替代指南中的显式证据规则。

### 11.3 提交前检查

- 病例级只选了一个结论；
- 目标病例信号有直接肺部证据；
- 待复核有明确触发原因；
- 否定、可疑、计划和他人证据没有被当成确定当前事实；
- 所有关系端点合法；
- 没有把病原体名称中的“肺炎”误标为肺炎诊断；
- 问题反馈不含身份信息。

## 12. 完整案例

### 案例1：明确当前肺炎

原文：“1周前发热伴咳嗽，今仍有发热。CT提示右肺炎症，门诊以‘肺炎’收住院。”

- 病例级：目标病例信号。
- 实体：发热；右肺炎症；肺炎；推荐新增后标咳嗽。
- 时间：1周前→发热；今→发热；仍有→发热。
- 说明：有索引事件内直接肺部证据。

### 案例2：急性发热加呼吸证据

原文：“发热1天，偶有咳嗽，双肺呼吸音粗，未行胸部影像。”

- 病例级：待专业复核。
- 实体：发热；推荐新增后标咳嗽。
- 不标：肺炎诊断、肺部感染、肺部组织炎症。
- 说明：符合急性发热加呼吸证据，但没有直接肺部证据。

### 案例3：孤立轻症

原文：“咳嗽1天，无发热，无胸闷气促，双肺未及啰音。”

- 病例级：非目标。
- 实体：发热，连接否定；推荐新增后可标咳嗽、气促并连接相应否定。
- 说明：孤立轻症，缺少急性组合和直接证据。

### 案例4：长期稳定咳嗽

原文：“反复咳嗽咳痰20年，心肺无殊。”

- 病例级：非目标。
- 时间表达：20年。
- 说明：长期稳定症状，无急性改变。

### 案例5：复杂胸腔感染

原文：“右侧脓胸，支气管胸膜瘘，胸水病原菌测序提示相关病原感染，近期无发热。”

- 病例级：待专业复核。
- 可标：胸水、mNGS、病原体、发热及否定。
- 不标：肺炎诊断、肺部组织炎症。
- 说明：胸腔感染严重但不等于肺实质肺炎。

### 案例6：非呼吸主诉中的偶然影像

原文：“因混合痔入院。影像见两肺纤维条索影及小斑片状影。”

- 病例级：待专业复核。
- 不标：肺部组织炎症，除非报告明确写炎症/感染/实变。
- 说明：性质和活动性不清，不能直接纳入目标。

### 案例7：住院期间肺炎已改善

原文：“入院胸部CT示两肺炎症。治疗后复查明显改善，现无发热咳嗽，予出院。”

- 病例级：目标病例信号。
- 实体：两肺炎症；发热、咳嗽连接否定（如相应标签可用）。
- 病例证据：治疗后改善。
- 说明：肺炎发生在同一次索引住院内；改善降低活动性，不删除病例信号。

### 案例8：纯既往肺炎

原文：“5年前曾患肺炎，本次糖尿病复诊，无咳嗽发热。”

- 病例级：非目标。
- 实体：肺炎并连接既往；发热连接否定。
- 说明：纯既往、与索引事件无关。

### 案例9：病原体弱阳性

原文：“呼吸道合胞病毒IgM弱阳性，肺炎支原体IgM阴性。”

- 病例级：若该句是全部可用内容，判非目标，不能仅凭血清抗体结果判肺炎；若同一索引事件另有急性呼吸证据，判待专业复核。任何情况下都不能仅凭该结果判目标病例。
- 实体：呼吸道合胞病毒、肺炎支原体、抗体IgM。
- 状态：弱阳性→呼吸道合胞病毒；阴性→肺炎支原体。
- 不标：“肺炎支原体”中的肺炎诊断。

### 案例10：计划排除肺炎

原文：“拟行胸部CT排除肺炎，无发热咳嗽。”

- 病例级：非目标。
- 肺炎：加可疑/假设性语境；不能当成已诊断。
- 说明：只有计划且缺少急性证据。

### 案例11：空文本

原文：空。

- 病例级：信息不足。
- 实体和关系：均为空。
- 运营动作：应由数据质量门禁在导入前拦截。

## 13. 疑难问题与上报

### 13.1 何时必须上报

- 两种解释会改变四分类；
- 指南和XML按钮不一致；
- 实体边界无法唯一确定；
- 一个修饰词可能连接多个不同实体；
- 原文损坏、截断或仍含身份信息；
- 出现当前Schema未覆盖、但可能改变病例判断的证据。

### 13.2 反馈必须包含

1. 任务号；
2. 去标识化的最小必要片段；
3. 问题类别；
4. 两种可能解释；
5. 对纳入、排除、优先级或解释的影响；
6. 本轮保守处理；
7. 希望指南明确回答的问题。

### 13.3 不允许的反馈

- 只写“不会标”“不确定”；
- 复制整份病历；
- 含姓名、证件号、电话或精确住址；
- 标注员自行宣布新规则或修改标签。

## 14. 质控指标和计算

### 14.1 先评病例级，再评结构化标签

建议顺序：

1. 病例级四分类一致性；
2. 核心肺部实体和关键症状；
3. 断言与时间；
4. 关系。

如果实体端点还不稳定，关系分数没有解释价值。

### 14.2 Cohen's kappa

两名标注员对同一批病例各给一个四分类结论。设：

- `Po`：实际一致比例；
- `Pe`：按两人各类别边际比例计算的随机一致概率；
- `kappa = (Po - Pe) / (1 - Pe)`。

例：20例中18例一致，`Po=0.90`。再根据两名标注员各自四类数量计算`Pe`，不能直接把0.90当kappa。

项目建议门槛，不是国际通用硬标准：

- kappa ≥ 0.80：可进入扩大试标；
- 0.67—0.79：分析分歧、修订指南并复测；
- < 0.67：暂停生产，重新培训和裁决。

即使总体kappa较高，也必须逐类报告目标、待复核、非目标和信息不足的混淆，避免类别不平衡掩盖目标病例漏标。

### 14.3 实体、属性和关系F1

计算前必须在输出中保存字符起止偏移。

- 严格实体匹配：标签、起点和终点全部相同。
- 重叠实体匹配：标签相同且跨度有重叠，仅用于诊断边界问题。
- 属性F1：实体匹配后比较状态/时间类别。
- 关系F1：关系类型和两个端点都匹配；本项目忽略点击方向，按语义角色归一化后比较。

分别报告precision、recall和F1，不只报一个总分。核心肺部证据、病原结果和病例级判断应单独报告。

### 14.4 完成率和问题门槛

进入生产前建议满足：

- 双标病例完成率 ≥ 95%；
- 未处理blocker = 0；
- 所有major问题有裁决和回归案例；
- 核心实体严格F1建议 ≥ 0.85；
- 关系F1建议 ≥ 0.80，且没有会反转病原结果的系统错误；
- 阶段1筛查排除样本经人工抽查后，无重复模式的目标病例漏筛。

### 14.5 当前20例AI前向测试结果

20例均可按本指南前身v0.2.0分类：目标2、待复核5、非目标11、信息不足2。发现6项major和2项minor，均已在v1.0.0中处理。该测试用于验证规则覆盖面，不是两名真人标注员的一致性证据。

## 15. 培训、双标与裁决

### 15.1 标注员培训

1. 阅读本指南和快速判定卡；
2. 由培训者讲解病例级四分类、时间三层模型和关系端点；
3. 共同完成5例示范；
4. 独立完成20例校准集；
5. 讨论分歧，但不覆盖原始答案；
6. 达到项目门槛后进入生产。

### 15.2 双标设计

- 第一轮：20—30例，100%双标；应覆盖明确肺炎、疑似肺炎、复杂胸腔病变、孤立轻症、纯既往、病原检测、无关病例和数据损坏。
- 扩大试标：50—100例，至少20%双标。
- 稳定生产：每批随机10%双标，并对高风险边界病例额外双标。

两名标注员必须独立完成，不能在提交前互看结果。

### 15.3 裁决

裁决员查看原始双份结果、指南版本和最小原文片段，逐项给出：

- 最终答案；
- 使用的规则；
- 分歧原因：指南缺失、培训不足、操作错误、数据问题或Schema问题；
- 是否修订指南；
- 是否回标历史数据。

裁决不是简单选A或B，也不能覆盖原始标注文件。所有裁决进入日志。

### 15.4 指南修订门槛

只有满足以下条件之一才增加标签：

1. 会改变病例纳入或排除；
2. 会改变复核优先级；
3. 是解释病例判断不可缺少的证据；
4. 在多例中重复出现，且现有标签无法稳定表达。

新增标签前必须说明定义、纳入、排除、正例、反例、合法关系、复杂度成本和回标需求。

## 附录A：快速判定卡

1. 空/损坏到不能判断？→ 信息不足。
2. 本次就诊/住院明确肺炎、肺部感染、肺部炎症/实变？→ 目标病例信号。
3. 疑似肺炎，或急性发热+呼吸证据，或当前肺/胸异常性质不明，或呼吸道病原阳性？→ 待专业复核。
4. 孤立轻症、长期稳定、纯既往、全部否定、单纯无关病历？→ 非目标。
5. 病原体名称不等于阳性；阳性不等于肺炎。
6. 胸水、条索影、小斑片影、结节、脓胸不自动等于肺炎。
7. 时间表达标原文，标准日期交给程序。
8. 关系只连明确归属；同句出现不够。
9. 点击先后不计医学方向；端点和关系类型必须正确。
10. 不确定时不猜，写最小片段和问题。
