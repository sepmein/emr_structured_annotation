# 肺炎相关EMR标注指南 v2.0.0 验证报告

日期：2026-08-28

## 1. 结论

v2.0.0完成了100份真实EMR去标识化节选、两名独立医学标注智能体和开发者裁决的探索性迭代。脱敏修复后的病例级一致率为0.94，Cohen's kappa为0.898。该数值只描述两套AI执行结果，不能解释为真人标注员间一致性或标签有效性证据。

本轮未报告因缺少新的时间或关系类型而无法作出病例级判断；主要问题来自四类边界和数据来源：慢性/非感染性肺部改变、明确替代病因、支气管扩张急性恶化、纯检验、连续诊疗旧证据、跨记录拼接和隐私字段。v2据此增加规则、案例和预处理要求，但仍需真人验证。

v2.0.0可作为真人受控校准的指南，但不能仅凭AI智能体结果进入大规模生产。智能体试标用于发现规则缺口，不替代两名真人医学标注员的一致性证据。

## 2. 测试设计

- 来源：`emr_merged_202608.json`中的真实EMR，去标识化后使用。
- 样本：100例，与Round 1的20例不重复，随机种子20260828。
- 分层：直接证据候选21、急性呼吸30、病原6、复杂胸部11、慢性呼吸2、普通负例20、低信息5、空文本5。
- 双标：A、B在互不查看结果的情况下按v1.0.0完成100例。
- 预登记：开发者在读取两份结果前记录7类预期问题和100例病例级参考解释。
- 裁决：先处理隐私阻塞，再比较病例级分歧，并检查两人一致但规则可能系统性错误的病例。

抽样关键词层只用于覆盖病例类型，不等于病例真值。节选最长1600字符，因此本轮是指南压力测试，不是完整病例金标准。

5个空文本被刻意保留，用于测试“门禁失败后仍进入任务时能否稳定回退到信息不足”；生产队列应在导入前拦截，不计入普通医学一致性主分析。

## 3. 脱敏修复

智能体B在R2-032、R2-044、R2-084发现姓名或住院号/床位字段并按指南停止。预处理规则随后增加结构化身份字段删除和高精度姓名模式；最终输入仅改变这3例，其余97例字节一致。A、B对修复后的3例独立复标并完全一致。

修复前输入保留为审计文件。当前输入经指定身份模式扫描未再命中，但生产仍需字段白名单、自动扫描和人工抽检共同验证。

## 5. 为什么高kappa仍需改指南

两名智能体都按同一份v1规则工作，因此可能一致地执行同一条过宽规则。开发者在查看结果前已预登记“慢性/非感染性肺炎或炎症”和“替代解释”风险。结果显示：

- R2-001被两人一致判目标，但只是非呼吸主诉中的少许慢性炎症；
- R2-017被两人一致判待复核，但肺占位已高度考虑肿瘤且无感染证据；
- R2-090、R2-100被两人一致判目标，但语境更符合稳定/改善中的慢性间质性肺病。

因此不能把一致率当作有效性。v2通过病例目标重新裁决，最终参考分布为目标18、待复核9、非目标62、信息不足11。

## 6. 时间模块探索性检查

三层模型继续成立：

1. 一个 `TimeExpression` 保存绝对日期、相对时间、时长、日序和窗口；
2. 当前/既往表达相对索引事件的位置；
3. 持续/进行性加重表达病程。

100例AI执行结果没有报告必须新增人工时间标签的案例。R2-031和R2-078的分歧来自“旧CT是否属于当前连续诊疗”，不是时间词类型不足。v2增加四项全部满足的判断：当前引用、治疗/复查延续、同一疾病过程、仍作为当前临床依据；无来源旧报告不自动并入。疑似跨记录错拼不靠时间标签解决，而是退回数据修复。该结论仍需真人标注验证。

## 7. 关系模块探索性检查

本轮问题反馈未报告因缺少因果、治疗或BEFORE/AFTER关系而无法完成病例级判断，因此暂不增加状态、时间、测量、标本、检测方式之外的关系。这不等于关系已验证。

主要风险是检验字段展平：项目、阳性/阴性、数值可能来自不同记录。v2要求只在同一检验记录组内连接，最近字符串不构成归属依据；无法唯一配对时不连、不触发阳性。Label Studio点击顺序继续不作医学方向评分，导出后按端点角色归一化。

当前智能体输出没有统一字符偏移和端点ID，因此不能报告严格实体F1或关系F1。这是下一轮真人结构化试标的前置修复项。

## 8. 标签复杂度裁决

本轮没有新增医学实体或关系类型。原因是所有新问题都可由以下方式解决：

- 病例级规则：慢性/非感染性、替代病因、支气管扩张急性恶化；
- 一个现有的通用时间表达提案；
- 数据问题控件；
- 预处理中的隐私、就诊拆分、重复去重和检验成组。

仍建议在生产XML加入：病例级四分类、咳嗽、咳痰、气促/呼吸困难、一个 `TimeExpression` 和 `data_issue`。不建议增加慢性炎症、支扩伴感染、稳定、好转、因果或完整时间图等新标签。

下一轮真人病例级校准使用 `schema_manifest_v2.0.0.json` 锁定的“当前XML + 外部病例表单”模式；同一批不得混入尚未批准的推荐标签。指南、成人/儿童XML哈希、病例表单字段和结构化导出字段均在清单中固定。

## 9. 自动校验

- 两份原始100例结果和两份脱敏复标结果均为有效JSON；
- 两份反馈均通过 `validate_feedback.py`；
- 修复后比较结果为有效JSON，100个任务无缺失；
- v2裁决参考、反馈裁决和Schema提案均为有效JSON；
- `schema_manifest_v2.0.0.json`锁定指南、成人/儿童XML哈希、外部病例表单和导出字段；
- `label_dictionary_v2.0.0.md`补充逐标签跨度、正反例、关系和病例作用；
- 当前100例输入通过本轮指定的隐私模式扫描；
- 指南和报告未修改生产XML。

## 10. 上线边界

在以下条件满足前，不建议开始大规模结构化生产标注：

1. XML或等价外部表单能保存病例级四分类；
2. 完成隐私、空白、重复、就诊拆分和检验成组门禁；
3. 使用完整去标识化就诊文本，并保存源文书和时间；
4. 两名真人医学标注员完成至少30例100%双标；
5. 病例级kappa达到0.80，所有目标/待复核重大分歧有裁决；
6. 结构化输出包含字符偏移和关系端点ID，才能计算实体和关系F1。
