# v2.0.1 指南开发决策日志

日期：2026-08-28

## 决策

1. 采用“一标签一卡”而不是继续扩充单张速查表。
2. 每张卡强制区分“医学定义”和“项目操作定义”。前者帮助理解，后者决定是否画实体、如何连关系以及是否影响病例级判断。
3. 对21个病原体逐一解释微生物类别和相邻概念，但统一保留“名称不等于阳性、阳性不等于致病、致病不等于肺炎”的项目边界。
4. 对标本和检测方式加入检验医学解释，重点区分呼吸道直接检出、培养、抗原、核酸、mNGS和血清学间接证据。
5. 对关系保留“点击方向忽略、业务角色不忽略”：评分可按端点角色归一化，但不能把任意同句实体视为有关联。
6. 对病例表单和data_issue也提供完整操作卡，明确这些不是医学实体、不在文本中画跨度。
7. 本次不改生产XML、不增加按钮、不调整病例规则，因此版本定为patch版本v2.0.1，默认不要求全量回标。

## 原因

项目的最终目的是稳定识别值得公共卫生复核的肺炎相关信号。定义不足会让标注员用各自医学经验补造证据；标签过多又会增加界面和一致性负担。详细字典把复杂度放在培训和查询文档中，而不放在生产Schema中。

## 下一步验证

- 用10—20个边界案例做开卷知识检查；
- 在20例培训集上记录每次查字典的标签、耗时和疑问；
- 将仍出现的分歧归为定义缺口、例子不足、Schema缺口或数据问题；
- 病例定义未变，因此真人独立验证仍按既定不少于30例计划执行。
