# 医学标注指南双角色迭代协议

## 角色

- `$medical-annotation-guide-developer`：开发指南、处理反馈、提出Schema变更。
- `$medical-emr-annotator`：按指南试标真实去标识化病例、记录问题，不修改规则。

## 单轮顺序

1. 指南开发者读取项目目标、当前XML、后端提示和既有指南，输出新版本指南及本轮试标计划。
2. 试标员锁定指南版本和XML哈希，完成指定样本，输出标注结果、结构化反馈和摘要。
3. 指南开发者逐条处置反馈，更新指南、变更提案、决策日志和下一轮计划。
4. 项目负责人批准涉及病例定义、标签或XML的实质变化。批准前，提案不视为生产事实。

## 建议迭代规模

- 第0轮：开发v0.1草案，使用5例覆盖主要路径。
- 第1轮：10例单人试标，优先发现阻塞、定义和边界问题。
- 第2轮：20例单人复测，包含上轮反例和困难案例。
- 第3轮：至少50例、2名独立试标者；评估病例级判断、实体、属性和关系的一致性。

样本应包含目标病例、非相关病例、仅既往、否定/可疑、计划检查、纯检验、空/短文本、复杂时间和并列关系。每轮保留一部分新病例，避免只对已知例子过拟合。

## 停止与发布

满足以下条件才形成实战版：无blocker；最近一轮至少90%无需临时规则即可完成；核心标签均有正反例和病例判断作用；双人一致性达到项目预设门槛；指南/XML/后端差异已修复或明确阻断发布。

建议参考门槛而非自动验收：病例级判断Cohen's kappa不低于0.80；核心实体/属性按严格或重叠匹配报告F1；关系单独报告，不能用总体准确率掩盖低频标签。

## 目录约定

每轮使用独立目录：

```text
runs/round-01/
  inputs/
  annotator/
  developer/
```

不得覆盖前一轮原始反馈。指南文件使用语义版本号，不使用“最终版”“最新版”。
