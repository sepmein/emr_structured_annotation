# 双人标注逐项核查与裁决方案

适用：多批Label Studio肺炎公共卫生信号标注导出。首批为项目221与230，各18例、每例两份标注。方案日期：2026-10-09。此文规定裁决操作，不代表本批已获得医学专家签署，也不改变现有标签定义。

## 本批结论与先处理的问题

病例级一致34/36，仅有221/T005、221/T290两例病例结论不同。项目221病例一致16/18、kappa=0.8269，项目230为18/18、kappa=1.0000。严格实体一致性F1分别0.5422、0.6525，总体0.5928；这是双人原始结果的一致性，不是对临床真值的准确率。不同项目A/B代表不同人员，不用合并kappa替代各项目质量判断。

本批49个实体标签中27个出现，22个未覆盖。未出现标签不能记为“一致100%”。全部49个标签的A/B数量、精确共同项及字典检查卡在核查报告和工作台中；9个属性字段全部列出，不把选填空白与必填漏填混为一项。5种关系全部核查，但91条导出关系都未保存类型，不能计算有效的关系类型F1。

本批存在32个同ID多标签选区、6条选区文字与偏移切片不相同的标签结果，以及1条关系自环。6条文字不匹配都涉及R前空格：不能假定病历整体偏移漂移，也不能不检查就自动strip后算通过。还有反向测量边、数值→单位的链式边、病原检测属性缺失/错填等问题。各问题记录可能指向同一个实体/关系，统计条数不能相加当独立错误数或错误病例数。

双方一致项必须检查。例如230/T053两人都标出当前肺部感染影像却仍选待复核，同时日期存在跨年矛盾；230/T249与230/T321两人均选非目标，但缺失引用病种/正文背景。221/T127是否真的信息不足、230/T200只有药品清单能否当非目标也要按项目规则重审。逐病例审阅建议已加入工作台，均为待人工确认。

## 每批输入先锁定，不能省略

1. 记录batch_id、源文件名、SHA256、导出时间、项目ID、LS任务ID、业务task_id、两名标注员、指南/字典/XML版本与哈希。初次导出没有项目配置，需从每个项目Settings导出当时配置后核实。此次用当前保留9个旧控件名的XML作候选检查合同，标签与控件名兼容不代表当时选项/界面完全一致。
2. 同项目同LS任务内配对两人。跨文件或跨项目用patient_id+serial_number等受控内部键建立映射，并核对全文SHA256；不能仅凭T005之类业务编号或文本长度对齐。当前两份文件是不同任务集合，不互相配对。
3. 遇到一人多份版本、超过两人、缺少一方、取消提交或草稿混入，明确哪些属于独立原始答案及其annotation_id后再审计。当前脚本对歧义报错，不自动选最后一份，也不把prediction当人工标注。
4. 确认标注文本是任务data.text原样字符序列，禁止比对前改空格、换行、标点、全半角；任何文本修复都要新版本、重定位或重标，旧偏移不能直接搬用。
5. 检查身份残留及字段异常。导出data中仍有patient_id、serial_number等字段，须由负责人确认是合法研究标识还是实际患者/就诊标识；派生报告隐藏这些值不等于原数据已经合格。发现实际身份残留，按项目隐私规则阻断该例并脱敏重取，记录阻断任务，不复制身份值到裁决理由。
6. 外部病例表单的1–3条必要原文证据、annotation_status、data_issue未在这两份导出中提供。先索取并绑定；不得把“文件未提供”写成“标注员一定没有记录”。信息不足可以0–3条证据，其余结论1–3条；隐私阻塞不作医学结论。

## 裁决顺序与逐项操作

### 第一步：技术阻塞项（P0）

先处理隐私/错拼、非法偏移、原文切片不符、属性无实体、关系悬空、自环、方向/类型缺失。原始结果照留，修复副本或新项目操作。

对本批91条无类型关系：技术负责人先用两份虚构短文本验证当前安装的Label Studio。分别创建“体温→数值（测量）”“发热→昨晚（起始时间）”，再完整JSON导出，确认每条relation保存labels且包含唯一合法关系类型，同时检查from_id、to_id、direction。既有项目当时是否没有选择关系类型、配置是否缺Relation按钮、导出链路是否丢字段，需看配置/界面和原任务，不能单从导出认定某个原因。

验证通过后，在裁决副本里逐条确定91条关系应保留、删除还是改端点，并重新选择类型、提交、导出。明确测量语境可提出“测量”候选，但程序不得直接把91条补成测量，因为其中有时间边、反向边和错误端点。不能只加类型而保留数值→单位链。

本批6条偏移文字差异：查看R所在原文和界面选区，精确记录旧start/end、旧value.text、data.text切片；按最短完整原则重选R，然后导出核对。多标签同ID要同时处理其所有labels条目、属性与关系引用，不能只修其中一个结果对象。

### 第二步：核定病例结论（P1，全部36例）

裁决员先阅读全文并确认索引临床事件，再看A/B，按指南§3–4先检查目标条件，再B1–B6、非目标、信息不足；不能先选择某个标注员再找理由。

| 情形 | 必须核实 | 具体处理 |
|---|---|---|
| 明确当前肺部证据 | 诊断/影像来源、患者主体、时间归属、否定/可疑/计划、慢性或充分非感染解释 | 四条件符合时目标；少许、好转、主诊断是其他病不自动排除 |
| 无直接肺部证据但需复核 | 指出命中B1–B6的具体编号和必要证据组合 | 有入口才待专业复核；孤立发热、湿啰音或病原名称不自动升级 |
| 慢性病稳定配药 | 病种是否已经明确、是否有本次加重+客观急性证据 | 足以判断而无入口则非目标，短文本不等于信息不足 |
| 前症/同前/如前/只给药表 | 被引用病种或证据是否缺失、是否会改变分类 | 缺失影响判断则信息不足并返补，不能靠药名推定背景 |
| 日期或病程冲突 | 同次病程变化、历史引用、日期替换、错拼分别是什么 | 能解释则逐提及记录；无法确认且反转结论则数据修复，不强行作医学金标 |

首批先审221/T005、T290两例真实分歧；再审230/T053、T249、T321、T200、221/T127等一致但存在规则风险的病例。每例记录最终类别、1–3条必要证据的精确偏移、规则条款、理由、裁决人、时间与是否回标。病例结论先定一个候选；完成实体和关系核查后还要复查一次是否受结构修正影响。

### 第三步：逐个实体标签核查（49标签，不遗漏未覆盖项）

工作台的49张卡已从当前字典逐条提取：操作定义、纳入、排除、最小跨度、适用属性、允许关系、混淆裁决。按以下过程逐标签完成，不仅查看计数。

1. 选择一个标签，查看该标签在A、B出现的所有病例和原始result。精确共同项也查；仅一方出现的看另一方重叠候选、原文及标签卡，判断漏标、错标、跨度还是同词不同提及。
2. 在原项目阅读全文寻找双方共同漏掉的必要证据。结果比对只覆盖两方实体并集，无法自动证明双方都漏掉的事实不存在；49卡要记录“已阅读全文确认未出现/不需标”或“未覆盖需补样本”，不能从计数0直接判无问题。
3. 确定保留、删除、更改标签、更改跨度、补充、合并重复六种动作之一；若合并，逐条记录old_region_id→new_region_id，并迁移对应属性与关系。
4. 最终实体同时记录start、end、text、唯一label、正确from_name与to_name。机械通气、时间和测量不强加临床属性，病原填检测属性。否定词、时间词等一般通过属性/独立时间实体表达，跨度最短完整。
5. 时间词上误带发热、数值/单位上误带体温/呼吸频率等，逐项删除错误类别；若一词在两个组误选，保留原记录供审计。现有旧控件可跨组同时选中，操作后每次核对选中标签；如要使用global-single必须明确迁移副本，不自动改原项目配置和历史导出。
6. 重复提及区分：同一位置同标签多个ID、同一选区多个result是重复候选；不同日期/不同检测各自保留；系统重复拼贴的同次证据按锁定口径处理。221/T170分别选主诉与现病史，不能只因字面一样就算严格一致。

本批明确示例：221/T076的肺炎支原体误用肺炎衣原体；T032的意识障碍误用三凹征；T127的93误用单位、%误用比较符；T018影像来源与诊断标签混淆；T005/T046两肺纹理增深/增多不直接映射肺炎影像。后三类仍要回看语境与病例B3，不用删除某标签就直接判病例非目标。

### 第四步：每个实体逐属性核查（9字段）

| 字段 | 裁决问题 | 空白如何处理 |
|---|---|---|
| finding_context | 是否明确存在、被否定、考虑/疑似、语境无法判断；共享否定作用域 | 适用必填实体不得空白，不能自动补肯定 |
| temporality | 此次提及当前/过去/未来/无法判断；与索引事件不是同一概念 | 必填；过去不自动已缓解，住院早期病程也不从病例删除 |
| clinical_course | 原文明写加重/好转/已缓解吗？是否存在状态明确不存在？ | 选填；无证据留空，明确不存在不填变化 |
| conditional | 条件下真实发生，还是无条件陈述？ | 仅适用临床实体必填；暴露不适用，不用否定替代条件性 |
| hypothetical | 已发生/被否定的现实事实，还是计划、假设、未发生？ | 适用范围内必填；计划并不代表患者已有疾病 |
| experiencer | 谁发生事件？患者、家属、其他人、无法判断 | 必填；接触事件主体与被接触者分别判断 |
| test_result | 同一次检测结果阳性、阴性、无法判断，还是非检测提及？ | XML非必填；原文明写检测必须记录，缺结果按规则判断，不因字段可空就漏填 |
| specimen_type | 痰、尿、血液等来自哪一检测组；原文确未说明吗？ | 非检测可不适用；检测未说明填原文未说明；不能从相邻咳痰推标本 |
| detection_method | 同组核酸/抗原/IgM/IgG/培养/滴度等 | 同上；IgG不能选抗体滴度/双份；明写方法必须保留 |

每个必填槽位由裁决员确认。统计分母只含适用且两边各有一个精确匹配实体的槽位。双方缺失、单方缺失、双方已填相同、双方已填不同分开；未匹配实体的属性在实体行一起核查，不从分母之外推“属性很好”。病原“原文未说明”和unknown/不适用不同。

首批专项：230/T038前三个病原检测属性缺失；221/T076柯萨奇病毒结果漏填；230/T093第二次肺炎支原体明写IgG，A漏填、B错用滴度/双份，双方都要改。230/T038“无发热”不同时填写好转；尿培养与痰培养不同检测组，不能把尿阳性挪作呼吸道阳性。

### 第五步：逐条关系核查（5类型，91条全部处理）

| 类型 | 允许方向和选择依据 |
|---|---|
| 发生时间 | 医学实体→明确事件时点；仅3天前发热不能自动解释为开始 |
| 起始时间 | 医学实体→明确开始时点；半天前开始出现发热优先此类型 |
| 结束时间 | 医学实体→原文明写结束/消失时点；过去、好转不自动结束 |
| 持续时长 | 医学实体→持续时长；3天≠3天前 |
| 测量 | 指标→数值、指标→单位、指标→比较符分别连接；不是指标→数值→单位 |

按关系编号逐条确认：端点存在且唯一类别正确→两者属于同一记录组/作用域→方向→类型→保留或修正动作。实体若修改/删除，所有引用它的关系都重新核对；删错实体不能留下悬空边。不得引入病原导致肺炎、药物治疗疾病等不存在于配置的类型。

例：T 36.5℃，最终应有T(体温)、36.5(数值)、℃(单位)，两条测量边T→36.5、T→℃。不能把单位反向连数值，不能把℃也标体温。关系起点/终点可能都曾同区误带多个标签，先解决实体类型再连。

### 第六步：签署、回读与冻结

每个核查项必须有状态：待裁决、需补信息、退回修复、已裁决。一致项也由裁决员确认，可写最终结构原样保留，原因类别填一致项确认；不允许最终答案为空但状态已裁决。

页面保存答案、证据偏移、规则、原因类别、理由、裁决人、时间、是否回标，导出JSON。证据偏移按[start,end)，最终实体/属性/关系建议使用JSON结构；任何“删除”记录写明被删ref和理由。无原文跨度的配置问题可证据偏移[]并引用问题编号，病例关键判断必须定位原文。

| 对象 | 最终答案示例 |
|---|---|
| 实体 | {"action":"replace","old_ref":"原核查ref","entity":{"start":82,"end":84,"text":"93","label":"数值","from_name":"measure_labels","to_name":"chief_complaint_text"}} |
| 属性 | {"action":"set_attribute","region_ref":"原核查ref","field":"detection_method","value":"抗体IgG"} |
| 关系 | {"action":"replace_relation","source_ref":"指标ref","target_ref":"单位ref","type":"测量","direction":"right"} |
| 病例 | {"case_decision":"非目标","rule_ref":"指南§3.2 C3","evidence_offsets":[[起点,终点]]} |

这份裁决JSON是审阅记录，不能直接当Label Studio导入文件；先由负责人根据已签署记录创建裁决副本，分配最终region ID并维护旧ID→新ID，再完整导出核查。当前脚本和页面不自动生成训练金标、不自动写回Label Studio。

本批发布前要求：原始1060条结果均在索引中可追溯；所有核查项签署或有明确阻断状态；阻断病例不进入冻结训练参考；49卡完成阅读全文查漏并记录未覆盖项；9属性按作用域补齐；91关系全部明确保留/删除/重建且合法导出；病例关键证据补齐；文本、元数据去标识化确认；配置版本真实锁定。最终副本再次运行脚本，P0必须归零，剩余语义候选经人工签署关闭。不要为了“零告警”删掉真实困难病例。

## 指南问题如何转成后续批次规则

建立独立规则台账：rule_id、问题模式、指南旧条款、裁决结论、新解释/例子、生效版本、影响标签与病例类别、触发检索条件、受影响批次/任务、是否回标、责任人、状态。示例：RULE-001跨组误选；RULE-002测量星形连接；RULE-003IgG与滴度区分；RULE-004缺失前症与稳定明确病种区分；RULE-005索引影像已改善；RULE-006纯检验片段与完整无关背景区分。

变更已有规则必须得到项目医学负责人确认，保留旧版指南和哈希。操作错误只需培训/重标，不必把错误做法写进指南。规则覆盖不清的（如T053时间矛盾、T005纹理异常是否B3）先登记需补信息或指南问题，不为提高一致率强行选择。

回标按问题模式查询全部历史批次，包括当时两人一致的记录；不只回标已列分歧。T127数值/单位误标属于操作模式，所有测量标签均需检查；T249缺前症属于病例规则模式，所有前症/同前/如前复诊都需查。规则变更后的裁决答案单独保存，不重写原始双标，也不把裁决后相同称为原始IAA提高。

## 下一批具体安排

| 阶段 | 操作 | 完成标志 |
|---|---|---|
| 1，整理输入 | 每项目配置/版本/哈希锁定；检查隐私、缺双标、人员版本、全文去重；外部证据表绑定 | 输入清单无歧义，问题病例有状态 |
| 2，校准培训 | 用本批模式制作5例共同示范，20例独立校准；包含跨组误选、否定、时间、IgG、两种标本、前症缺失、测量关系 | 讲评并形成确认的规则台账 |
| 3，独立复测 | 不少于30例新病例，覆盖高风险边界及本批22个未覆盖标签中的适用例；两人提交前不可见彼此结果 | 只用原始独立答案计算项目内指标 |
| 4，发布门槛 | 按指南病例kappa建议≥0.80、核心实体严格F1≥0.85、关系严格F1≥0.80、完成率≥95%；P0未解决不得发布 | 罕见/未覆盖标签单列，不用高总分掩盖核心错误 |
| 5，扩大与稳定 | 50–100例扩大试标至少20%双标；稳定后每批随机10%双标，高风险另加双标；本批问题未闭环前保持100% | 每批有独立指标、裁决记录、规则漂移/回标台账 |

## 可重复运行的命令

以下命令从仓库根目录运行。项目绑定示例暂用当前XML，取得真实项目配置后替换路径；输出必须是新目录，脚本拒绝覆盖非空裁决目录。

```powershell
python scripts/audit_double_annotations.py --input data/double_annotation_review_batch_001_20261009_v001/batch_1/project-221-at-2026-10-09-15-12-779a9bc2.json data/double_annotation_review_batch_001_20261009_v001/batch_1/project-230-at-2026-10-09-15-12-3fd57eb3.json --project-config 221=label_studio/pneumonia_config.xml --project-config 230=label_studio/pneumonia_config.xml --review-notes data/double_annotation_review_batch_001_20261009_v001/batch_1/review_notes_2026-10-09.json --output data/double_annotation_review_batch_001_20261009_v001/batch_1/review_2026-10-09_final
```

后续批次替换--input、项目配置和--output；--review-notes可省略，或由审阅者按“项目/业务task_id”新建该批建议JSON，包含rule、recommendation、evidence_offsets字段。不能把首批病例建议直接套到别批同名任务。

测试：`python -m unittest discover -s tests -v`；文档链接：`python documentation/annotation/scripts/check-document-links.py`。这些检查只验证解析、计数与追溯，不验证实际Label Studio界面、医学裁决正确性或模型性能。
