## 4. 导出与参考数据形成

### 导出内容

保留Label Studio原始JSON快照和当时XML：任务ID、稳定患者代号、原文`data.text`、两份独立`annotations`、标注者与标注ID、取消状态、实体字符起止偏移、关系端点、实体属性及病例级选择。平台版本与导出方法在执行时记录。

患者分组使用项目内可追溯的稳定代号，展示材料不暴露原始身份信息。原始快照进入受控数据位置，不提交到Git。

### 核对与裁决

1. 统计有效任务、唯一患者、唯一文本及每条有效标注份数；区分未完成、已取消、空白、重复和信息不足。
2. 验证字符偏移对应同一原文，实体文本与`text[start:end]`相符；关系端点必须存在；属性指向相应实体；每病例结论唯一且范围合法。
3. 无实体的记录需要区分“已完整检查但没有目标实体”和“尚未标注”。前者作为负例保留，不能默默删掉。
4. 两份标注原样保留，逐层比较病例结论、实体跨度/标签、属性及关系。分歧记录由指定医学裁决者确认，形成另外的裁决版。
5. 一致病例也安排复核抽查，防止两人共同遗漏。独立测试集最好采用不展示模型答案的标注流程，减少评价参考受到模型预标注影响。
6. 人工一致性报告与模型评价报告分别形成；前者记录指南与操作稳定性，后者记录预测相对裁决参考的效果。

## 5. 数据划分与训练前后对照

### 初始划分提案

按患者分组，先排查精确与近重复文本跨集合，再分训练、验证、最终测试。可讨论约60%/20%/20%的起始分配；若最终确为200条且患者分组允许，大致为120/40/40条。它是初始提案，不是已确定的样本配额，也不代表40条足以评价所有49类。

分配时检查症状标签和判别类别覆盖。稀有类别不足时如实展示支持数量，优先补样本；不能将测试样本回流训练后仍将其称为独立测试，也不能因测试结果不理想反复挑换样本。

症状抽取和判别模型尽量沿用同一患者划分，以便后续评价端到端流程。裁决参考可以覆盖整批，但训练、调参及模型选择只能使用相应训练/验证部分。

### 对照实验

- 按当前字典建立并复核正则实体基线，只依据训练/验证部分调规则，最终测试前冻结规则版本和推理代码；保存与模型相同原文的原始预测。规则是实体提及抽取，不自动判断否定状态或病例结论。
- 冻结“训练前”任务模型及其标签映射，在独立测试集生成原始预测，保留失败和截断记录。
- 用训练集训练，验证集选择参数或模型，冻结“训练后”产物。
- 在同一测试原文、同一裁决参考、同一评价程序上比较正则、训练前与训练后预测，逐标签展示增加或下降的结果。
- 两个模型输出类别不同或某标签原先不支持时，注明不可直接比较；不能默认为训练前该标签正确率为零。
- 如果当前只有基础语言模型而没有可用任务模型，应先明确有意义的任务基线；新分类头随机输出不能包装成现有预标注能力。

若判别模型输入采用抽取结果，还需区分两类实验：一是固定判别模型、分别输入训练前后抽取结果，观察上游变化；二是在各自相同的数据条件下训练并比较整个流程。不得把人工参考实体输入的判别效果直接描述为模型预测实体输入时的端到端效果。

## 6. “每标签准确率”的具体口径

### 实体抽取

主口径为实体跨度和类别同时正确，基于每条记录内的一对一精确匹配计算：

- TP：预测与参考的起止位置及标签均一致。
- FP：多出的预测、标签错误或边界不符的预测；边界或标签错误相应产生参考漏检。
- FN：未被正确匹配的参考实体。
- 精确率P = TP / (TP + FP)。
- 召回率R = TP / (TP + FN)。
- F1 = 2TP / (2TP + FP + FN)。

每标签保存TP、FP、FN和参考数量，展示三种方法的P、R、F1，以及模型相对正则、训练后相对训练前的变化。可另列宽松边界分析用于错误定位，但主对照保持同一严格口径。NER没有天然有限且有业务意义的“所有非实体跨度”分母，不能用大量非目标字符的正确率替代实体识别质量。

若业务确实需要“每条病历是否出现某标签”的准确率，则另外建立病例—标签二值表，在明确分母后计算TP、FP、FN、TN及准确率，并同时给出召回率和阳性比例。该表评价标签出现与否，不评价跨度定位；也不自动表示患者当前有该症状。

### 判别模型

待确认目标后，报告总体准确率、每类别精确率/召回率/F1和混淆矩阵。各类别列出测试数量，错误按业务含义分析。若涉及公共卫生复核，后续明确哪些漏检最重要，并增加对应召回率和复核工作量统计。

模型规模、输入信息、类别合并方式及参考标准随目标一起确定。当前不承诺判别准确率或选择未经确认的目标类别。

## 7. 速度评价

| 测量对象 | 对照 | 指标 |
|---|---|---|
| 症状/实体抽取 | 正则、训练前模型与训练后模型 | 相同计时层的P50/P95延迟、成功吞吐、失败/超时率 |
| 小型判别模型 | 目标明确后的基线与训练版，若具备可比基线 | 相同速度指标；另记输入是原文还是抽取特征 |
| 联合流程 | 实际接通后 | 抽取到判别的整体耗时、失败率和整体有效吞吐 |

同一硬件、相同文本集合、批量大小、并发和预热条件下测量。保存每次请求/记录的状态与耗时，并统计原文和token长度、实际截断比例。成功请求延迟与全部失败/超时数量同时报告；吞吐按整段实际时间计算。

正则现有工具测本地CPU抽取，不包含文件读写或网络；不得直接与模型HTTP端到端延迟计算倍数。正式比较需补齐相同计时范围；无法统一时分列本地抽取和完整服务响应，并说明条件差异。

已新增[模型服务预测与测速客户端](model-service-benchmark.md)，单条请求对接现有`/predict`，输出首轮正式预测及重复测速，直接接入三方评分。当前完成模拟及本机临时HTTP验证，真实模型联调未开展；token和截断信息因接口未提供而保留未知。

现有最大长度默认1024个token，实际环境参数待核实。质量评价使用完整参考，并报告截断造成的证据丢失；测速需对应实际处理覆盖范围。
