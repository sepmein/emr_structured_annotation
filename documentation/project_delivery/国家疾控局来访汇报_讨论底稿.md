## 一、目标与建议主线

通过多轮讨论，形成覆盖建设思路、指南研发、工具建设、标注进展、初步结果和下一步计划的完整汇报。重点补齐初步结果的评价口径、实测证据及展示方案。

建议主线：围绕肺炎相关公共卫生信号识别需求，将电子病历中的原始信息转化为有规范、有原文证据、可复核的结构化数据，逐步验证人机协同标注与模型抽取的质量和效率。

业务链条：监测需求 → 数据整理 → 指南与标签体系 → 独立标注与裁决 → 模型训练与评价 → 人工复核的信号输出。

这是一条建设和验证路径。当前各环节完成程度需分别说明，不能把代码实现或文件流程描述为已通过端到端应用验收。

## 三、本轮已经核查的项目事实

### 1. 当前规范与工具

- 当前指南和标签字典正文版本为v2.2.0“成人与儿童统一配置适配草案”，文件名沿用v2.1.1；修订日期为2026-10-07。
- 文档声明已按统一XML核对标签、属性和关系，尚未完成Label Studio页面验收和人工双标验证。
- 当前统一XML有49个实体标签、9个实体属性字段、5种关系和1个病例级选择控件。
- 数据合并脚本按患者及就诊标识合并多表，生成任务文本及年龄分组；该脚本不是脱敏工具。
- 标注平台采用Label Studio，本项目建设页面配置与相关工具；应分别说明平台采用与本地开发的贡献。
- ModernBERT代码提供实体识别、关系抽取、预测转换和训练触发；不应称为已经完整支持实体属性和病例结论预测。
- 双标比较与裁决已有文件式试验流程。历史双标主体为智能体，不能表述成已完成真人医学双标。
- GLiNER路线已于2026-10-08退出当前代码，历史试验记录只作历史依据。

### 2. 数据准备

本地2026-10-08批次汇总记录：329条源记录，327条可解析，2条JSON截断；建议导入156条，信息不足待补充38条，含待补充的候选池194条。

156条为39条“优先保留”与117条“边界及对照保留”的合计，不等于156例目标病例或156例已验收标注。327条可解析记录涉及186名唯一患者，156条建议导入记录涉及86名唯一患者，记录数与患者数须分开。

该批次经过辅助初筛与语义核对，不是临床专家逐字双标或四分类金标准；隐私处理仍需人工标注前验收。汇报若引用，应先确认是否作为本次正式批次。

### 3. 历史指南压力测试

Round 3：200个任务，双智能体病例级原始一致率96.0%；全文精确去重后158个唯一文本，一致率95.6%，描述性Cohen's kappa为0.879。

这些数据可说明指南在该批历史样本上的规则压力测试与分歧发现情况，不能代表真人一致性、当前模型准确率或新版配置的有效性。裁决还发现两套流程共同犯错的案例，说明一致性之外仍需独立复核。

Round 2与Round 3样本构成不同，不能用94%到96%的简单比较证明指南效果提升。

试验规模可以概括为5→20→100→200个任务，但应逐轮说明方法：5例探索、20例AI前向试标、100例及200例双智能体试标。20例前向试标摘要明确记录两个独立子智能体在落盘阶段失败，不能把全部轮次统称为已完成双智能体双标。各轮任务数也不应汇总为已验收人工标注总量。

## 四、重点讨论：初步结果怎样展示

### 1. 模型抽取质量

拟展示：关键标签的精确率、召回率和F1，严格实体跨度及标签匹配结果，关系端点、方向及关系类型均正确的端到端结果。总体结果与关键类别结果同时呈现，并标注每类测试样本量。

先核对：是否已有训练模型、训练样本规模、当前标签版本、人工裁决测试集，以及既有训练与测试的分离方式。建议按患者分组，并检查重复和近重复文本，避免同一患者或同文进入训练与测试两侧。

现有代码的NER评分为token级macro指标；RE使用标注实体对评分。可作为训练监控依据，但两者均不能直接替代严格实体级F1及端到端关系F1。当前训练选择模型时使用NER F1与RE F1之和，该数值也不能当成一个百分比准确率。

进一步代码核查：训练入口按记录随机打乱后以默认80%/20%切分，未实施患者级分组或重复文本跨集合检查；样本不超过20条时全部用于训练，未留验证集。任务转换选择首个非空标注结果，未见显式选择裁决版的逻辑。这些是正式补测前需明确处理的数据协议问题，不能仅凭训练日志证明泛化效果。

配置中的默认最大长度为1024个token，训练和服务预测均有截断调用；实际部署参数须现场核实。补测需统计截断比例、截断后丢失的参考实体/关系及完整文本端到端效果，不能将截断区域的遗漏从整体评价中悄然移除。

若未来展示病例级信号识别效果，需先明确实际产生该结论的模型或规则流程，并以独立专家参考评价；不能用实体模型的F1代替病例级效果。

### 2. 模型运行速度

拟展示：单条记录端到端延迟中位数、P95延迟、每分钟处理记录数、失败率；必要时单列模型推理耗时。

每次报告附硬件、模型及标签版本、文本长度分布、批量大小、并发数、是否预热与计时范围。长病历应说明截断或分段处理情况，避免速度数字掩盖内容丢失。

仓库已有手工联调与压测脚本，可作为后续补测起点；本轮未运行服务压测，也未找到可直接引用的本项目模型测速结果。

2026-10-09补充：负责人确定最终与本地通用大模型比较，可先用外部模型测试。拟使用左右长度—耗时分布图、中间关键统计及下方同资源医院容量情景。已实现[配对记录制图与容量情景工具](../model_evaluation/model-speed-capacity-comparison.md)及[Chat Completions抽取/测速入口](../model_evaluation/chat-model-benchmark.md)，完成明确标注的虚构记录、模拟及临时HTTP验证；指定真实服务联调、同资源持续负载与业务量仍待补充，不能将延迟比值直接当作医院承载倍数。

### 3. 人工标注效率

拟比较：纯人工标注与模型预标注后人工修订，分别完成同等质量结果的每例耗时、返修情况及遗漏情况。

测试应平衡样本难度和人员经验，避免重复阅读同一病例带来熟悉效应。提速结论需以质量没有明显下降为前提，模型推理快不能直接等同于整体标注效率提高。

### 4. 原文到结构化证据的案例

拟展示2—3例经过验收的去标识化案例：原文 → 实体与属性 → 关系 → 病例结论及原文证据。至少包含一例成功提取、一例需人工纠正的边界情形，必要时展示信息不足如何回源补充。

展示目标是让听众理解信息如何支撑复核，不将示例当成整体效果证明。

## 五、建议补证顺序

1. 确认汇报目的、日期、时长、听众及现有人工标注和训练的实际进展。
2. 对齐当前指南、字典、界面与输出协议，确认现阶段可实际演示的功能。
3. 确定人工校准及独立评价样本，优先保证关键标签和边界案例覆盖；样本量根据时间、资源及预期用途再定。
4. 用冻结版本完成抽取质量、速度及人工效率的小规模实测，保留数据与结果口径。
5. 据证据决定汇报中哪些写“已完成”、哪些写“初步验证”、哪些写“下一步计划”，再完善讲稿与展示材料。

已建立讨论框架和证据清单，并新增本地导出核查、参考选择、分组划分、正则基线、逐标签评分、测速与独立训练入口；现有训练模块增加可选验证记录及显式清单路径，原`fit()`行为未切换。真实标注、实际训练与服务压测仍待开展。
